# red-is-a-stop

A red required check on the integration branch, or on any branch another step is stacked on, is a stop. On the integration branch it is the first task, not background noise. Nothing new is branched, stacked or merged onto red.

**Applies when** starting any task, cutting a branch, opening a PR, adding or rebasing a step in a stack, or asking a human to merge. Read the latest run on `develop` first. Before adding or rebasing a step, read the latest run on the branch that step stacks on. Especially when the failure took 0 s or has no job log: that is a broken workflow, not flaky infrastructure.

**The decision it changes.** The first commit, and whether the next stack step may move. Red on the integration branch is the first task. Instead of the feature, the agent fixes the check (or surfaces it if the cause is outside its scope) and adds a structural guard so the same red cannot return silently. When any step in a stack goes red, the agent fixes that step before adding or rebasing any step above it. Steps below the red one are unaffected. Waiting on a person, such as a pending merge or review, is not this stop ([conventions/git.md](../conventions/git.md)). A step that merged on green and later goes red counts as red on its target branch. Work that was already stacked on red is rebased once green. The agent does not merge the fix itself ([keep-human-gates](keep-human-gates.md)).

**Source.** Pull requests recorded in the archive repository were merged onto a `develop` whose `validate.yml` had been failing in 0 seconds because of an unquoted colon in a step name. The failure was found a day later and fixed in a later pull request recorded in the archive repository, with a guard in `scripts/check-structure.js` so it cannot return silently. The learn draft is recorded in the archive repository. Which branches count, and what a step that merged on green and later goes red counts as, was decided in [ADR-0023](../docs/decisions/0023-red-stops-a-stack.md) ([issue #54](https://github.com/shedcollective/neat-os/issues/54)).
